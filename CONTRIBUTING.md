# Contributing

We would love for you to contribute to Zephyron. This project is a difficult task, and our mission is to make contributing enjoyable and educational for everyone. All contributions, issues, documentation, and improvements are welcome. No contribution is too small.

## How to Start?

If you are unsure where to start, check the sections below to see where help is needed. You can reach out with questions on our [Discord](https://discord.gg/GSeTUeA) server or submit an issue for guidance.

## Code of Conduct

Help us keep Zephyron open and inclusive. Please read and follow our [Code of Conduct](/CODE_OF_CONDUCT.md).

## Mission

Zephyron is built by the people, for the people, regardless of who they are or where they are. We believe everyone deserves the right to privacy.

Please read our [Rules](/RULES.md) as an extension for moral high grounds before contributing.

## Pull Requests

Our branch naming convention is:

`TYPE-ISSUE_ID-DESCRIPTION`

For example:

```text
doc-548-submit-a-pull-request-section-to-contribution-guide
````

Where `TYPE` can be:

* **feat** - a new feature
* **doc** - documentation changes
* **cicd** - CI/CD changes
* **fix** - a bug fix
* **refactor** - code changes that neither fix a bug nor add a feature
* **security** - security-related changes

All pull requests must include a commit message describing the changes made.

### Standard Workflow

1. Fork the repository.
2. Clone your fork.
3. Pull the latest changes from upstream.
4. Create a branch using the naming convention above.
5. Make and test your changes.
6. Commit your changes.
7. Push your branch.
8. Open a pull request.
9. Address review feedback.
10. Once approved, a maintainer will merge the pull request.

## New Features

For significant features, please open an issue before submitting a pull request.

Features affecting the network protocol, anonymity, encryption, routing, identity, relay behavior, or metadata should be discussed before implementation.

## Security

If you discover a security vulnerability, please do not open a public GitHub issue. Follow our [Security Policy](/SECURITY.md) instead.

Please do not test vulnerabilities against other users, public relays, or third-party infrastructure without permission.

## Other Ways to Contribute

You can also contribute by:

- Reporting bugs through GitHub Issues.
- Improving documentation.
- Reviewing pull requests.
- Helping other contributors.
- Sharing ideas and improvements.
When reporting a bug, please include enough information to reproduce it, including relevant logs, steps, and your environment.
